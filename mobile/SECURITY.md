# Mobile Hub 安全与授权边界

## 可信边界

工厂是员工、权限、消息、任务、结果的事实源。Hub 是受信任的鉴权/路由服务，持有业务快照，因此 **Hub 不是端到端盲中继**；服务器必须由用户控制。每台工厂的 Connector 只允许预定义动作，并将 Hub principal 映射到本地明确授权 actor。恶意 Hub 仍在本地 grants 和原工厂权限内受限，不能调用任意 shell、路径或 Codex RPC。

## 身份与请求

- Netlify 固定密码模式：另行生成高熵应用密码，只持久化带随机盐的 scrypt 校验值，失败次数按可信平台 IP 的哈希持久限速；不是网页源码内的万能码，也不是 SSH/Netlify 账号密码。只有 owner 应知道该密码；需要撤销密码持有者时必须另行轮换密码，单独撤销旧会话不能阻止其再次登录。
- 配对/设备接入码：256 位随机，10 分钟、一次性，存储哈希；由手机签发的码随签发者撤销而失效。
- 手机：Secure、HttpOnly、SameSite=Strict、`__Host-` Cookie；服务器校验配置的 Host、Origin 和 CSRF。令牌不放 localStorage 或查询参数；首次链接使用 fragment 并立即从地址栏移除。
- 手机角色：viewer / operator / owner，另有设备 scope；目标工厂再检查本地 role 和 `message:send` / `work:assign`。手机不能自己指定 actor/from。
- 设备：独立随机凭证，Hub 根据凭证决定 deviceId；结果必须匹配命令、设备、digest 和 delivery nonce。新设备在目标本地绑定 actor。
- 撤销：立即阻止新访问、排队操作和后续授权；已经被工厂接受的任务不会因此停止。正在执行的网络请求存在不可消除的竞态，以原工厂执行事实为准。
- 管理秘密：仅用于 SSH/本机恢复配对，独立于手机 Cookie；公网反向代理屏蔽管理路由。SSH host-key 不匹配必须带外验证。

## 数据与重试

- Netlify 后端每次强一致读取，并使用 ETag 条件写入处理多实例竞争。未提交成功不返回登录 Cookie、设备租约或命令确认；只允许当前 published production 部署与固定站点，避免预览/旧代码读取相同 Blobs store。云端持有快照与回执，是可信服务端，不是端到端加密的盲转发。
- 命令规范化后计算摘要；未知字段拒绝，保留字 ID 拒绝，令牌/执行身份不能由客户端字段覆盖。
- 本地 ledger + 原工厂幂等键防止 talk/assign/create 重复提交；更新/上传的不可证明崩溃窗口明确返回需人工确认，不声称 exactly-once。
- 不记录/转发原始工具参数、任意文件路径；可见员工正文可能由员工自己包含路径等内容，这是原消息内容，不是额外文件 API。
- 图片仅 PNG/JPEG/WebP/GIF、单张 10 MiB、对话最多 6 张，经原附件模块验证；预览必须关联目标员工请求/job 或本人上传，不能传任意路径。
- Web Push 端点强制可信推送服务域名、HTTPS，无自定义端口/账号，避免将订阅变成 SSRF；发送前再次检查撤销与 scope。通知不含任务正文。
- API 永不被 SW 缓存；离线写禁止；会话过期/撤销后清除本地目录缓存。用户主动打开的目录缓存仍可能留在丢失设备上，应由手机锁屏保护。

## 运维限制和已知风险

- JSON 状态带进程锁和原子替换，不是数据库事务/高可用集群。必须单 writer；掉电持久性、磁盘空间与备份需要运维保障。
- 默认结果/操作记录有保留窗口，但本地工厂 ledger 和原工厂记录未自动删除：避免删掉防重证据。需要按实际规模另行制定保留和容量策略。
- HTTPS 代理是唯一公网入口。不要公开 8787、app-server、8791 或未经鉴权的本地 API；不要使用 Tailscale Funnel；不要忽略 TLS 校验。
- Node/依赖升级先跑测试；安装固定 lockfile、`--ignore-scripts`。后台推送是可选能力，其运行故障不能影响任务执行事实。
- 手机图片、长历史和大任务板快照存在容量上限；出错应明确提示，不用静默丢弃数据来假装同步成功。
- 当前没有进行真实异地网络与 iOS/Android 真机验收；实现及自动测试通过不能替代这些验收。
